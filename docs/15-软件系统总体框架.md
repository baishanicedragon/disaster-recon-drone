## 15.1 范围与定位

- 硬件已冻结（v0.4：双翼、两桶、倒拖起飞、无动力改平）。本设计是「硬件之外的额外软件设计」。
- 涉及**两套软实体**：

  | 实体 | 语言/平台 | 运行位置 | 实时性 |
  |:---|:---|:---|:---|
  | **机载嵌入式固件** | C（裸机/RTOS） | 飞控 MCU + 视觉 MCU + WiFi 模块 | 硬实时、确定性 |
  | **安卓手机 APP** | Kotlin/Java（Android 10+） | 操作员手机 | 人机节奏，非实时 |

- 不写正式代码，只给：模块职责、状态机、通讯帧、数据格式、素材库（地形图源、识别参考物模板）。

## 15.2 分层架构

```
┌──────────────────────────────────────────────────────────────────────┐
│  L3  素材库 / 外部源（离线可缓存，任务前预取）                          │
│   · 地形图源注册表（DEM / 卫星底图 / 灾时影像）                         │
│   · 识别参考物模板库（设施 / 人体 / 车辆残骸 …）                       │
│   · 协议常量表（门控阈值、状态字、帧格式）                             │
└───────────────▲───────────────────────────▲──────────────────────────┘
                │ 拉取(源/模板)               │ 读取(常量)
┌───────────────┴──────────┐      ┌──────────┴───────────────────────────┐
│  L2  安卓 APP             │      │  L1  机载固件                         │
│   · 地形图抓取+航迹编译   │◀────▶│   · WiFi 配对 + 任务下发              │
│   · 参考物标注 UI         │  WiFi │   · 检查单采集 + 状态机             │
│   · 配对/检查单/时序监控  │  AP   │   · 飞行时序(段I~IV, 见09)          │
│   · 返程振铃 + 标布校验   │      │   · 末端识别流水线 + 落盘           │
│   · 双通道回收 + 分享     │      │   · >20m 切断 + 落地断电 + 烟雾     │
└──────────────────────────┘      └──────────────────────────────────────┘
```

**关键边界（硬规则）**：
1. **L1 是自主的**：一旦高度 > 20 m 切断指令链路，L1 完全按预先下发的任务文件 + 09 章时序运行，不依赖 L2。
2. **L2 不下凡任何实时控制**：L2 只做「准备 / 监控 / 回收」，飞行中唯一的下行指令是 `ABORT`（仅 < 20 m 有效）。
3. **L3 是素材不是逻辑**：源注册表/模板库只是数据，抓取与编译逻辑在 L2，消费逻辑在 L1。

## 15.3 模块划分

### 15.3.1 机载固件模块（L1）

| 模块 | 职责 | 对应既有 |

| `datalog` | 影像/标注/遥测落盘 microSD | 扩展 09 |
| `recover` | 落地断电 + 烟雾释放 + 二次配对回传 | 新增 |
| `comm_cut` | > 20 m 监听高度、切断指令链路 | 新增 |

### 15.3.2 安卓 APP 模块（L2）

| 模块 | 职责 | 本文档 |

## 15.4 端到端数据流（一次任务生命周期）

```
[准备]  APP: src_mgr 探测源 → map_fetch 抓取任务区 DEM+影像
        → traj_compile 生成 mission.bin → roi_annot 圈注参考物 → 并入 mission.bin
        → pairing 连飞机 AP
[配对]  飞机 boot→WIFI_PAIR(灯闪) ←→ APP 握手 → APP 下发 mission.bin
        → 飞机 mission_rx 校验 → 进入 PREP，回报「待检查单」
[检查单] APP checklist_ui 顺序显示：①电压灯 ②机翼/桨限动器 ③导线
        → 飞机 checklist 回报各状态字 → 全绿 → APP「起飞就绪」
[起飞]  人员撤离 → APP 按「起飞」→ 飞机 ARMED→CLIMB(段I 倒拖)
        ├─ 高度<20m 且收到 ABORT → ABORT：就地回收(降+断电)
        └─ 高度>20m → comm_cut 切断指令链 → RUN(段II~IV 自主)
[返程]  APP flight_mon 按任务文件 ETA 显示倒计时
        └─ T-10min → 振铃 + 提示前往回收场 + 标布相机校验(recover_ui)
[落地]  飞机 DESCEND→LAND → 断电 + 烟雾
[回收]  人员返回：
        ├─ 主体可加电 → 再配对 → recover 回传视频+标注图 → APP
        └─ 已摔坏   → 拔 microSD → 手机 USB 读卡器 → tf_reader 解码 → APP
[分享]  APP share → 微信/钉钉/邮件 发指挥部
```

## 15.5 顶层状态机

### 15.5.1 机载状态机（`fms`）

```
        boot OK
   BOOT ──────────▶ WIFI_PAIR ──配对成功──▶ PREP
   │                (灯:慢闪)              (灯:快闪, 待检查单)
   │                                          │ checklist 全绿 + ARM
   │                                          ▼
   │                                      ARMED ──▶ CLIMB (段I 倒拖)
   │                                       │              │
   │                          ABORT(<20m)  │      alt>20m │ comm_cut
   │                                       ▼              ▼
   │                                   ABORT_RECYCLE   RUN (段II~IV 自主)
   │                                   (降+断电)        │
   │                                       │           段IV末 │
   │                                       │              ▼
   │                                       │          DESCEND → LAND
   │                                       │              │ 落地检测
   │                                       │              ▼
   │                                       │           CUTOFF+SMOKE
   │                                       │              │
   │                                       └──────┬───────┘
   │                                      可加电? │
   │                                       ┌──────┴───────┐
   │                                  RECOVER_WIFI   RECOVER_TF(拔卡)
   │                                       │              │
   └──────────────────────────────────────┴──────────────┘
                                              ▼
                                           END (数据已交 APP / 已落卡)
```

**状态语义表**

| 状态 | 进入条件 | 行为 | 指示灯 |
|:---|:---|:---|:---|
| BOOT | 上电 | 自检（IMU/电池/桨锁/SD） | 常亮红 |
| WIFI_PAIR | 自检过 | 起 AP `HDRS1_XXXX`，等握手 | 慢闪蓝 |
| PREP | 配对+任务校验过 | 等检查单，回报状态字 | 快闪蓝 |
| ARMED | 检查单全绿+ARM | 桨待转，最后 3 s 自检 | 蓝常亮 |
| CLIMB | ARM 超时/起飞 | 段 I 倒拖爬升，监听 ABORT | 绿闪 |
| ABORT_RECYCLE | CLIMB 中 alt<20m 收 ABORT | 就地降高+顺桨+断电 | 黄闪 |
| RUN | alt>20m | 切断指令链，段 II~IV 自主 | 绿常亮 |
| DESCEND | 段 IV 末 | 无动力/动力迫降剖面 | 绿闪→红 |
| LAND | 落地检测 | 断电 + 触发烟雾 GPIO | 红闪 |
| RECOVER_WIFI | 落地后可加电 | 重启 AP，回传数据 | 慢闪蓝 |
| RECOVER_TF | 不可加电 | 等拔卡（无动作） | 灭 |

> **comm_cut 的硬规则**：进入 RUN 后，`wifi_link` 仅保留**单向遥测 beacon**（若有余量），
> **丢弃一切下行指令**；ABORT 在 RUN 态被忽略。这一条是安全边界，不能用软件开关绕过（参考 09 章 IL 互锁思路，写进 `comm_cut` 的不可屏蔽逻辑）。

### 15.5.2 APP 状态机

```
CONNECTING ──连上AP──▶ CHECKLIST ──全绿──▶ READY ──按起飞──▶ FLYING
   │                      │                 │                │
   │ 搜不到AP             │ 任一项红         │ 未撤离禁止     │ alt<20m可ABORT
   ▼                      ▼                 ▼                ▼
 RE-SCAN              BLOCK             BLOCK          (ABORTABLE↔MONITORING)
                                                  alt>20m │
                                                          ▼
                                                   MONITORING(只读遥测)
                                                          │ T-10min
                                                          ▼
                                                   RETURN_ALERT(振铃+标布)
                                                          │ 落地报告
                                                          ▼
                                                   RECOVER(WiFi活体 / TF死体)
                                                          │ 数据到手
                                                          ▼
                                                   SHARE ──▶ END
```

## 15.6 关键设计决策（与用户需求逐条对应）

| # | 用户需求 | 本设计落点 |
|:--:|:---|:---|
| 1 | APP 自动搜索地形图网站并编译航迹 | `src_mgr`+`map_fetch`+`traj_compile`（16.2~16.4）；**「自动搜索」实现为「源注册表 + 自动探测可用性/覆盖」，非无脑爬虫**——见 16.2 可行性说明 |
| 2 | 输入末端 AI 识别参考物（设施/人体/残骸）并圈注 | `roi_annot`（16.5）→ 导出 ROI 模板并入 mission.bin → 机载 `detect` 推理圈注 |
| 3 | WiFi 待配对指示灯 → 传入数据 → 起飞准备 | `boot`/`wifi_link`/`PREP` + 指示灯语义（15.5.1） |
| 4 | 检查单：电压/机翼桨限动器/导线 | `checklist` 状态字 + `checklist_ui` 顺序确认（16.7） |
| 5 | 20 m 内可撤销就地回收；> 20 m 切断通讯 | `comm_cut` + `ABORT_RECYCLE`（15.5.1）；20 m 阈值写协议常量 |
| 6 | 返程显示时间，差 10 min 振铃 + 标布校验 | `flight_mon` ETA + `recover_ui`（16.8~16.9） |
| 7 | 下落、落地断电、释放烟雾 | `DESCEND`→`LAND`→`CUTOFF+SMOKE`（15.5.1） |
| 8 | 活体再配对回传 / 死体拔卡 USB 读 | 双通道 `RECOVER_WIFI` / `RECOVER_TF` + `tf_reader`（16.9） |
| 9 | 图片经手机分享微信/钉钉/邮件 | `share`（16.10） |

## 15.8 待确认 / 待实测（设计阶段开放项）

- **地形图自动抓取可行性**：公开源（Copernicus/OpenTopography/Sentinel 开放访问）有 API；但「自动搜索任意网站」不可靠，本设计采用**注册表 + 自动探测**路线，需用户拍板是否接受。
- **WiFi 距离/带宽**：ESP32 AP 实测有效距离与任务文件体积需核（mission.bin 预估 < 2 MB）。
- **识别模型选型**：端侧轻量模型（如 YOLO-Nano / MobileNetV3-SSD）是否够覆盖「人体/车辆残骸/设施」，待实拍样本回流后训练。
- **20 m 阈值**：以气压+GNSS 融合 AGL 为准；GNSS 拒止时退化到纯气压，误差需评估。
- **标布校验相机**：用手机后置相机，不依赖机载；仅做「标布是否在框内、朝向是否对」的引导，不做 AI 识别。

> 以上开放项不影响框架合并；落地编码前由 12 章验证流程补实测。
