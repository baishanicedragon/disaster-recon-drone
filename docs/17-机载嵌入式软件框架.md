## 17.1 硬件接口需求（新增，需 07 章补）

| 接口 | 信号 | 用途 | 备注 |
|:---|:---|:---|:---|
| 待配对指示灯 | RGB LED | `boot`/`WIFI_PAIR`/`PREP` 状态 | 见 15.5.1 指示灯语义 |

## 17.2 顶层状态机详述（对应 15.5.1）

`fms` 主循环每 10 ms 调度；以下为各状态的核心动作与出口条件。

### 17.2.1 BOOT
- 上电 → IMU 零偏自检、电池电压、桨锁/顺桨开关、SD 挂载。
- 任一失败 → 常亮红 + 蜂鸣，停。（不进 PAIR）
- 全过 → 转 `WIFI_PAIR`。

### 17.2.2 WIFI_PAIR
- 起 AP `HDRS1_<sn4>`（sn4 = 机身序列后 4 位），灯慢闪蓝。
- 等 APP 握手 + `MISSION`；收齐且 SHA256 校验过 → `mission_rx` 解析 → 转 `PREP`。
- 超时（建议 5 min 无配对）→ 回到 BOOT 或低功耗待机（待定）。

### 17.2.3 PREP
- 灯快闪蓝；`checklist` 持续采集状态字回报 APP。
- 收 `ARM` 且 `checklist` 全绿 → 转 `ARMED`；否则忽略 ARM。

### 17.2.4 ARMED
- 桨待转，最后 3 s 静止自检（IMU 稳、电压稳）。
- 超时未起飞 → 回 `PREP`。
- 起飞指令（APP 按「起飞」或本体按钮，二选一）→ 转 `CLIMB`。

### 17.2.5 CLIMB（段 I 倒拖）
- 段 I 逻辑（09 章）：被动摆式 + 阻尼 + 推力，爬升到 150 m。
- **`comm_cut` 持续监听 AGL**：`alt < 20 m` 时 `ABORT` 有效；`alt ≥ 20 m` → 触发 `comm_cut`（切断下行指令链）→ 转 `RUN`。
- 段 I 末（到 150 m）→ 段 II 撑开 + 2.0 g 拉平（既有 `deploy_ctrl`）。

### 17.2.6 ABORT_RECYCLE（仅 < 20 m）
- 收 ABORT → 顺桨 + 降高 + 断电；灯黄闪。
- 落地 → `CUTOFF+SMOKE`（轻烟，示位）→ 转 `RECOVER_WIFI`（若可加电）。

### 17.2.7 RUN（段 II~IV 自主）
- **指令链已切断**；仅 `wifi_link` 可选保留单向 beacon（遥测），**丢弃所有下行**。
- 执行 mission.bin：撑开 → 拉平 → 巡航(段III) → 目标区盘旋识别(段IV) → 返航。
- 段 IV 末 → 转 `DESCEND`。

### 17.2.8 DESCEND → LAND
- 下降剖面（见 06 章）：机头朝下/可控迫降，净空余量用完即触地。
- 落地检测：加速度突变 + 速度≈0 持续 0.5 s → 转 `LAND`。

### 17.2.9 LAND → CUTOFF + SMOKE
- 立即断主电（保留 RTC/SD 供电完成写盘）→ GPIO 触发烟雾 1 次。
- 灯红闪。

### 17.2.10 RECOVER_WIFI / RECOVER_TF
- 可加电：`RECOVER_WIFI` 重启 AP，等 APP 再配对回传 `datalog/`。
- 不可加电（摔坏）：进入 `RECOVER_TF` 等待拔卡；无动作，灯灭。

## 17.3 WiFi 配对协议（框架）

### 17.3.1 物理
- 飞机 AP：`HDRS1_<sn4>`，开放或 WPA2（密钥印于机身），信道 6/11。
- APP 直连，不联网；链路仅任务前/回收时使用。

### 17.3.2 帧格式（详见 17.8）

| 方向 | 帧 | 说明 |
|:---|:---|:---|
| APP→机 | `HELLO{app_ver}` | 握手 |
| 机→APP | `READY{hw_ver,status}` | 状态=WIFI_PAIR |
| APP→机 | `MISSION{bin,sha256}` | 任务文件 |
| 机→APP | `ACK{sha256,PREP}` / `NAK{reason}` | 校验结果 |
| 机→APP | `CHK{volt,wing_lock[4],prop[4],wire}` | 检查单状态字（PREP 期周期发） |
| APP→机 | `ARM` | 检查单全绿后 |
| APP→机 | `ABORT` | 仅 CLIMB 且 alt<20 m 有效 |
| 机→APP | `BEACON{seg,alt,eta,kwh}` | RUN 期可选单向遥测 |

## 17.4 `comm_cut`：> 20 m 切断（安全边界）

```
伪代码（不可屏蔽逻辑，独立于 fms 调度）：
  if state == CLIMB and AGL() >= 20.0:
      link.drop_downlink()        # 此后 ABORT 被忽略
      if beacon_enabled: link.set_tx_only()
      transition(RUN)
  # RUN 态收到 ABORT -> 直接丢弃，不进状态机
```

- 阈值 `COMM_CUT_ALT = 20.0 m` 写协议常量（17.8），**不可经 APP 改写**。
- AGL = 气压高度 − DEM 高程（08 章地形匹配）；GNSS 拒止时退纯气压，误差标注于遥测。

## 17.5 末端识别流水线 `detect`（扩展 09 章）

```
相机(段IV盘旋) → ISP → 推理(轻量模型, 见15.8) → NMS
  → 与 mission.bin 的 roi[] 匹配(cls 一致) 
  → 命中: 在帧上画框 + 写 annotations.json{cls,conf,geo,poly}
  → 未命中期望数: 标 "MISSING" 告警
  → 全部帧 + 标注 落 datalog/
```

- 模型输入：下视相机（STA 460 窗口，09/04 章已定下翼前方无遮挡）。
- 输出：圈注图（JPEG 叠加）+ `annotations.json`（机器可读）。
- 与 09 章 `detect` 流水线共用；本设计补「ROI 模板匹配 + 缺失告警」两层。

## 17.6 数据落盘 `datalog`

microSD 目录（与 09 章快拆数据舱同卡）：

```
/datalog/<task_id>/
 ├── video.mp4          # 段IV 盘旋录像（含圈注叠加）
 ├── annotations.json   # 识别结果（geo + cls + conf）
 ├── frames/            # 关键帧 JPEG（可选，省空间可只留标注帧）
 ├── telemetry.log      # 全任务遥测（seg/alt/spd/kwh/t）
 └── mission_echo.bin   # 回显所用任务文件（溯源）
```

- 写盘在 `LAND` 断电前完成（RTC/SD 独立小电源保最后 200 ms 写盘）。
- 死体回收：`RECOVER_TF` 拔卡 → 手机 `tf_reader` 读上述目录。

## 17.7 任务文件 `mission.bin` 格式（草稿 v0.4）

```
[HEADER]  magic="HDRS" ver=u16 crc32=u32 size=u32
[TRAJ]    wp_cnt=u16
          wp[i]: lat_i32(1e7) lon_i32(1e7) alt_agl_i16(m) spd_u8(m/s)
          fence_cnt=u8  fence[j]: lat/lon(同编码)   clear_h=u16(净空m,默认150)
          recover: lat/lon/alt  marker_expect: x,y,heading
[ROI]     roi_cnt=u8
          roi[k]: cls=u8(见16.5.1) poly_cnt=u8 poly[](lat,lon)
                  label[24] priority=u8 expect_cnt=u8
[PARAMS]  vs_thresh=f32(20.9) h_deploy_min=u16(90)
          comm_cut_alt=f32(20.0) loiter_sec=u16(300) return_margin=f32(1.15)
[TAIL]    sha256[32]
```

> 所有多字节小端；坐标 int32 定标 1e7（cm 级）。正式编码前由 09 章固件团队定最终对齐。
