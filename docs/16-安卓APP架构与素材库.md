> **状态：设计框架（无试验机，未正式编码）。** 本文档是 [15 章](./15-软件系统总体框架.md) 中 L2 层的展开：

> 只给架构与数据格式，**不写正式业务代码**。

## 16.1 APP 技术基线

| 项 | 选型（建议） | 说明 |
|:---|:---|:---|
| 语言 | Kotlin（Jetpack Compose UI） | Android 10+（API 29+） |
| WiFi | `WifiNetworkSpecifier` / `WifiManager` 直连 AP | 连飞机 `HDRS1_XXXX`，不走互联网 |
| 地图 | MapLibre Android（离线矢量）+ 自绘 DEM 晕渲 | 避免高德/百度 SDK 联网依赖 |
| 影像解码 | Coil / BitmapRegionDecoder | 大卫星图分块 |
| 分享 | `ACTION_SEND` Intent 隐式分发 | 微信/钉钉/邮件共用系统分享表 |
| USB 主机 | `UsbManager` + 读卡器（mass storage / MTP） | 死体回收通道 |
| 持久化 | Room（任务/源缓存）+ 文件沙箱 | 源与模板离线可缓存 |

> **设计原则**：APP 全程**不依赖公网**。地形图/影像在任务前于有网处预取落盘；飞行中纯本地。

## 16.2 模块一：地形图源注册表 `src_mgr`（「自动搜索」的实现路线）

### 16.2.1 可行性说明（重要）

用户原话「APP 自动搜索需要的地形图网站」。现实约束：

- 任意网站的 HTML 结构多变，**无脑爬虫不可靠、易碎、且多违反 ToS**。
- 可靠做法是**「源注册表 + 自动探测」**：预置一批合规开放数据源（API/标准瓦片），
  APP 启动时按「任务区经纬度 + 分辨率需求 + 当前网络」**自动探测哪些源覆盖、哪些可用**，
  择优拉取并缓存。这等价于用户要的「自动找到能用的图」，但工程上稳。

### 16.2.2 源注册表（素材库 · 地形图源）

| 源 ID | 类型 | 分辨率 | 覆盖范围 | 获取方式 | 合规/备注 |
|:---|:---|:---:|:---|:---|:---|
| `COP_DEM30` | DEM | 30 m | 全球 | Copernicus Open Access (API) | 开放；垂直精度 ~4 m |
| `ALOS_AW3D` | DEM | 30 m | 全球 | JAXA 注册下载 | 需注册，开放 |
| `GS_CLOUD` | DEM/影像 | 30 m / 2 m | 中国 | 地理空间数据云 gscloud.cn | 国内；资源三号/高分 |
| `OPEN_TOPO` | DEM | 1~30 m | 全球 | OpenTopography API | 开放；部分地区 1 m |
| `SENTINEL2` | 光学影像 | 10 m | 全球 | Copernicus Open Access | 5 天重访，**灾时最新底图** |
| `LANDSAT9` | 光学影像 | 15 m | 全球 | USGS EarthExplorer | 16 天重访 |
| `GF_DISASTER` | 光学影像 | 0.5~2 m | 中国 | 高分专项应急通道 | **需申请**；窄谷最实用 |
| `T_DOMO` | 影像瓦片 | 瓦片 | 全球 | 天地图（需 key） | 国内底图，需 key |
| `OSM` | 矢量底图 | — | 全球 | OSM 瓦片/Overpass | 开放；路网/居民点 |

> 注册表是**数据不是逻辑**：每条含 `{id, type, endpoint, auth, bbox_filter, res, license}`。
> `src_mgr` 据此自动探测覆盖与可用性，不硬编码爬取脚本。
> **灾时优先 `SENTINEL2`（时效）+ `GF_DISASTER`（精度）**；预规划用 `COP_DEM30`+`GS_CLOUD` 补高分 DEM。

## 16.3 模块二：地图抓取 `map_fetch`

输入：任务区 `bbox`（起飞 P0 + 目标 P1 外扩缓冲，建议 ±2 km）、分辨率需求。

流程：
1. `src_mgr` 返回可用源 → 按「DEM 必选 + 影像至少 1 个」组包；
2. 并发拉取 → 落 `mission_staging/`：
   - `dem.tif`（GeoTIFF，WGS84/UTM）
   - `sat.jpg`（灾时/近期影像，带地理参考）
   - `vec.mbtiles`（OSM 路网/居民点，可选）
3. 校验：bbox 完整、无空洞（空洞区在 08 章净空里加倍处理）、坐标系统一。

> **失败降级**：若高分源不可达，自动降到 `COP_DEM30` 并在任务卡标注「净空已提到 150 m（08 章对策）」。

## 16.4 模块三：航迹编译 `traj_compile`

调用 [08 章](./08-自主导航与山区穿越.md) 8.3 算法（填洼 → 谷底线提取 → 走廊净空 150 m → 航点序列），产出机载任务文件：

```
mission.bin 结构（v0.4 草稿，详见 17.7）
┌────────────┬───────────────────────────────┐
│ hdr        │ 魔术字 HDRS / 版本 / 校验和     │
├────────────┼───────────────────────────────┤
│ traj       │ 航点表[wp_i(pos,alt_agl,spd)]  │
│            │ 地理围栏 polygon + 净空 150 m   │
│            │ 回收场 R0 坐标 + 标布预期位     │
├────────────┼───────────────────────────────┤
│ roi        │ 参考物模板[见 16.5]             │
├────────────┼───────────────────────────────┤
│ params     │ vs_thresh/h_deploy_min/20m阈值 │
│            │ 盘旋时长/返航余量等（见 02 章） │
└────────────┴───────────────────────────────┘
```

APP 在地图上**可视化航迹 + 净空走廊**供操作员确认；确认后随任务下发飞机。

## 16.5 模块四：识别参考物标注 `roi_annot`

用户在 `sat.jpg` 上圈注「末端 AI 识别参考物」，导出 ROI 模板并入 mission.bin。

### 16.5.1 参考物模板库（素材库 · 识别参考物）

| 类别 | 模板 ID | 标注内容 | 机载 detect 用途 |
|:---|:---|:---|:---|
| 设施 | `FAC_BUILD` | 建筑轮廓 + 名称 | 灾情比对（倒塌/完好） |
| 设施 | `FAC_BRIDGE` | 桥面 + 两端 | 通道可用性 |
| 设施 | `FAC_SHELTER` | 帐篷/安置点 | 受灾人口聚集 |
| 人体 | `HUMAN` | 单人框 + 姿态(卧/立) | 幸存者定位 |
| 残骸 | `WR_VEH` | 车辆残骸框 | 失事/埋压点 |
| 残骸 | `WR_DEBRIS` | 大型瓦砾堆 | 滑坡范围 |
| 自定义 | `CUSTOM_n` | 自由框 + 文本标签 | 用户指定目标 |

每个模板字段：`{id, cls, polygon_geo, label, priority, expect_count}`。
`priority` 决定圈注配色与返航后排序；`expect_count` 用于「未发现即告警」。

### 16.5.2 标注 UI 流程

```
打开 sat.jpg → 缩放到任务区 → 长按拖框 → 选类别(16.5.1) → 填标签/优先级
→ 存为 ROI → 全部完成后「并入 mission.bin」
```

> **圈注的是地理坐标（polygon_geo），不是像素**：机载 `detect` 推理出匹配目标后，
> 把结果（框 + 类别 + 置信度 + geo）写回影像与 annotations.json，供回收时查看。

## 16.6 模块五：配对 `pairing`

```
APP 扫 AP `HDRS1_XXXX*`
  → 直连（WifiNetworkSpecifier，不联网）
  → 握手：APP 发 HELLO{app_ver}，飞机回 READY{hw_ver, status=WIFI_PAIR}
  → APP 发 MISSION(mission.bin) → 飞机回 ACK{sha256, PREP}
  → APP 进入 CHECKLIST
```

- 配对期**单向下发**；飞机不主动推流（省电、降干扰）。
- 任务文件带 SHA256，飞机校验失败回 `NAK` 要求重传。

## 16.7 模块六：起飞检查单 `checklist_ui`

顺序确认（飞机回报状态字驱动，不可跳步）：

| 步 | 检查项 | 数据来源 | 红灯含义 |
|:--:|:---|:---|:---|
| ① | 电压指示灯 | 飞机 `checklist` 电池状态字 | 电芯 < 3.5 V / 压差 > 0.2 V |
| ② | 机翼/螺旋桨限动器 | 翼锁销微动 + 桨顺桨开关 | 任一片半翼未锁 / 桨未顺桨 |
| ③ | 导线连接 | 配电回路导通检测 | 主供电/ESC 回路开路 |

三项全绿 → APP「**起飞就绪**」；任一项红 → 阻断起飞，提示现场处置。

> 检查单是**软硬双保险**：飞机 `checklist` 模块也独立判，两端不一致以飞机为准（飞机不 ARM）。

## 16.8 模块七：时序监控与撤销 `flight_mon`

- 显示：当前段（段 I/II/III/IV）、高度、距返航 ETA、剩余能量（来自任务文件预算）。
- **撤销（仅 < 20 m）**：`flight_mon` 在 alt<20 m 显示「撤销」按钮 → 发 `ABORT` → 飞机 `ABORT_RECYCLE`。
- **> 20 m**：按钮变灰，提示「已切断指令链，自主飞行中」；此时 APP 仅只读遥测（若 beacon 仍在）。
- ETA 由任务文件预规划 + 实测进度推算；**T-10 min 触发 RETURN_ALERT**。

## 16.9 模块八：返程振铃 + 标布校验 + 双通道回收 `recover_ui` / `tf_reader`

### 16.9.1 返程振铃 + 标布校验

```
T-10min → 手机振铃(VIBRATE+铃声) + 弹窗「前往回收场 R0」
→ 人员到现场 → APP 开相机对准标布
→ 叠加引导框：标布是否居中/朝向是否对(按 mission.bin 预期位)
→ 偏移 → APP 文字/箭头指示「左移 2 m / 旋转 90°」
→ 人员调好后确认 → 等落地
```

- 标布校验**只用手机相机 + 几何引导，不做 AI 识别**（简单可靠）。
- 标布规格建议：≥ 2 m × 2 m 高可视色（橙/荧光），带方向箭头。

### 16.9.2 双通道回收

| 通道 | 条件 | 流程 |
|:---|:---|:---|
| **WiFi 活体** | 落地后主体可加电 | 飞机 `RECOVER_WIFI` 重启 AP → APP 再配对 → 飞机推 `video.mp4` + `annotations.json` + `telemetry.log` → APP 导入 |
| **TF 死体** | 已摔坏不可加电 | 拔 microSD → 插手机 USB 读卡器 → `tf_reader` 挂载 → 解码 `datalog/` → 导入 |

- 两通道导入后统一进 APP 本地库，按 ROI 模板排序展示（含圈注图）。

## 16.10 模块九：分享 `share`

```
选中图片/标注图 → ACTION_SEND
→ 系统分享表：微信 / 钉钉 / 邮件(指挥部地址预填)
→ 附 annotations.json 摘要(可选)
```

- 微信/钉钉走系统分享 Intent（不集成私有 SDK，避开审核与密钥）；
- 邮件：预填指挥部地址（任务卡配置），主题含任务 ID + 回收时间。
