只在**倒拖/改平段控制**与**能量管理**两处写自定义代码。

## 9.2 任务层：等距相机触发

盘旋时用**距离触发**而非时间触发，保证重叠率稳定：

```
已知：GSD = h × p / f
     地面幅宽 W_ground = W_px × GSD
     要求前向重叠 75 % → 相邻帧地面间距 = 0.25 × W_ground（沿航向）

每当地速积分距离 ≥ 0.25 × W_ground 时触发一次快门

示例：h = 250 m，GSD = 6.5 cm，W_px = 4056（横向）
     W_ground(沿航向) = 3040 px × 0.065 = 198 m
     触发间距 = 0.25 × 198 = 49.5 m
     @ 23 m/s → 每 2.15 s 一帧
     盘旋 10 min（600 s）→ 约 279 帧
     存储：279 × 12 MP JPEG（≈ 5 MB）= 1.4 GB  ✅ 远小于 256 GB
```

> **重叠率选择**：75 %/60 %（航向/旁向）是 SfM 的常规要求。
> 盘旋时旁向重叠由**圈间半径差**提供——盘旋半径保持恒定会导致旁向重叠不足。
> **对策**：盘旋半径按 **150 m → 140 m → 130 m** 阶梯收缩（每 3 圈降一档），
> 或让盘旋中心每次偏移 20 m，形成"玫瑰线"式覆盖。

## 9.3 识别算法（视觉 MCU 通道）

### 9.3.1 模型选择

| 模型 | 参数量 | 输入 | 在 STM32N6 上的目标帧率 | 用途 |
|:---|---:|---:|---:|:---|
| **YOLOv8n** | 3.2 M | 256×256 | **≥ 15 fps** ⚠ | 主模型 |
| YOLOv5n | 1.9 M | 320×320 | ~20 fps | 备选 |
| NanoDet / PP-PicoDet | < 1 M | 320×320 | ~25 fps | 备选（更轻） |
| FOMO（Edge Impulse） | 极小 | 96×96 | > 30 fps | 极轻，仅粗定位 |

> **量化**：必须 **INT8 量化**（NPU 只跑整数）。量化后 mAP 下降 2~4 个点，可接受。

### 9.3.2 类别定义

| 类别 | 说明 | 备注 |
|:---|:---|:---|
| `person` | 人体（站/卧/部分掩埋） | **最高优先级** |
| `vehicle` | 车辆、工程机械 | |
| `structure` | 建筑残骸、屋顶 | |
| `cross_red` | 回收场红布十字标 | 用于迫降精定位 |
| `debris` | 大型堆积物 | 辅助判读 |

### 9.3.3 数据集策略（**真实灾区数据不可用**）

⚠ **本仓库不包含、也不应包含任何真实灾区影像。**

| 策略 | 做法 |
|:---|:---|
| 公开数据 | COCO / VisDrone / DOTA 中 `person`、`car`、`truck` 类 |
| 域适应 | **关键问题**：公开数据集是无灾场景，与"淤泥覆盖的残骸"差异巨大 |
| 自建数据 | 用**本地相似环境**（河滩、工地、山地道路）自行采集，人工标注 |
| 合成增强 | 随机加泥浆色/遮挡、低对比度、阴影、部分掩埋（裁剪 + 颜色变换） |
| 期望值 | **不要指望高召回率**。YOLO 在这里的角色是**"打点提示"**，不是"判定" |
| 人工判读 | **12 MP 影像的人工判读才是主手段**，YOLO 只是加速筛选 |

> **诚实的定位**：在 250 m 高度、6.5 cm GSD 下，一个 1.7 m 的人体约 **26 × 26 像素**。
> 这个尺寸对 YOLOv8n 来说属于**小目标困难区**，召回率能有 50~70 % 就算不错。

### 9.3.4 输出与打点

```
每帧输出：
  { frame_id, timestamp, lat, lon, alt_amsl, roll, pitch, yaw,
    detections: [ {cls, conf, x_c, y_c, w, h} ... ] }

写入 CSV / JSONL 到 microSD，与影像文件名对应
飞控同时通过 MAVLink 接收高置信度目标 → 记入飞控日志（双份）
迫降后 LoRa 信标首帧包含：**目标计数摘要**（如 "P:12 V:5"）
  → 人员在赶来的路上就知道值不值得快一点
```

## 9.4 影像后处理（地面，非机载）

```
microSD → 工作站
   ↓
1) 几何校正（相机内参标定：棋盘格，起飞前做一次）
   ↓
2) SfM / 正射拼接（OpenDroneMap / COLMAP / Metashape）
   输入：影像 + 每张的 GPS/姿态（EXIF + 日志文件）
   输出：正射影像（GeoTIFF）+ DSM + 点云
   ↓
3) 变化检测（若灾前有影像）
   灾前（卫星/历史航片） vs 灾后正射 → 差分 → 快速圈定变化区
   ↓
4) 人工判读 + YOLO 预打点辅助
   ↓
5) 输出疑似目标清单（坐标 + 缩略图）交救援方
```

> **开源工具**：**OpenDroneMap（ODM）** 是最合适的——完全离线、可本机跑、
> 输出 GeoTIFF 正射与 DSM，救援方能直接用 QGIS 打开。
> 这一点很重要：**灾区没有网络，云端处理服务不可用。**

## 9.5 倒拖段 + 改平段控制（自定义，最小实现）

```c
// 段 I（倒拖爬升）：被动摆式为主，只做阻尼 + 推力，不做全姿态闭环
// 周期 500 Hz（与飞控同频）

typedef struct {
    float kp_climb;     // 爬升率 P 增益
    float kd_rate;      // 角速率阻尼增益
    float target_rate;  // 目标爬升率 (m/s)
    float h_cutoff;     // 关机高度 = 150 m
    float vs_thresh;    // 撑开门控空速 = 1.1 Vs ≈ 20.9 m/s
    float h_deploy_min; // 撑开门控最低高度 = 90 m
} vtolup_ctrl_t;

// 段 I 主循环：推力 = f(爬升率误差)，差动 = f(角速率) 仅做阻尼
void vtolup_control(vtolup_ctrl_t* s,
                    float h, float climb_rate,
                    float w_meas[3],      // 陀螺角速率
                    float out[4])         // 4 个电机推力指令
{
    // 1) 总推力：高度 < 关机高度时保持爬升率
    float thrust = 1.0f;
    if (h < s->h_cutoff)
        thrust = 0.72f + s->kp_climb * (s->target_rate - climb_rate); // 0.72 ≈ 悬停油门
    else
        thrust = 0.0f;   // 关机

    // 2) 阻尼：4 电机差动产生与机体横滚/俯仰角速率反向的力矩
    //    （倒拖时"横滚"即绕水平轴的倾斜，摆式稳定 + 此阻尼即可）
    float d_p = s->kd_rate * w_meas[0];
    float d_q = s->kd_rate * w_meas[1];

    // 3) 分配（X 型，相邻反向）
    const float ang[4] = {PI/4, 3*PI/4, 5*PI/4, 7*PI/4};
    for (int i = 0; i < 4; i++) {
        out[i] = thrust * 0.25f
               + d_p * sinf(ang[i]) + d_q * cosf(ang[i]);
        if (out[i] < 0.0f) out[i] = 0.0f;
    }
}

// 段 II~IV 由任务状态机（08 章 8.6）驱动，本文件只给出门控判定：
//   撑开门控：  airspeed >= vs_thresh && height >= h_deploy_min
//   拉平门控：  wings_locked && pitch_rate 受控
//   重启门控：  pitch < 15 deg && airspeed > 1.15 Vs && ratchet_on_cruise_pitch
```

> ⚠ **这是示意代码，未编译、未测试。**
> **强烈建议的降级路径**：先**分步验证**（[03 章 Q2](./03-总体方案与气动布局.md)）——
> ① 系留测倒拖爬升（只验证推力 + 阻尼）；② 滑翔机投放测无动力改平（不装电机）；
> ③ 全剖面合练。倒拖段不做全姿态闭环，靠摆式稳定 + 阻尼大概率足够。

## 9.6 日志与取证

| 日志 | 位置 | 内容 | 采样 |
|:---|:---|:---|:---|
| 飞控日志 | 飞控 SD | 全参数、IMU、GPS、控制输出 | 默认（ArduPilot .bin） |
| 视觉日志 | 数据舱 microSD | 每帧检测结果 + 置信度 | 每帧 |

> 也无法在出事后判断"是设计问题还是操作问题"。
